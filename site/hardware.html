01 / Native drivers

Native device drivers

Native drivers use vendor SDKs or serial protocols. Verified below means the named check is recorded for that device. Supported means an implemented driver path, without the same recorded check. Neither label certifies every control or a full unattended night.

Recorded checks and implemented driver paths
Device Connection Status Evidence and limits
ZWO AM5N mount USB serial Verified Native movement and tracking checks are recorded for an AM5N.
ZWO AM5 family USB serial Supported The family driver exists; the recorded native validation names the AM5N.
ZWO ASI220MM ASICamera2 SDK Verified SDK properties and gain checks are recorded. Native cooler and anti-dew control are not implemented.
Other SDK-enumerated ZWO ASI cameras ASICamera2 SDK Supported The native adapter discovers SDK-listed cameras. Native cooler and anti-dew control are not implemented.
Player One Poseidon-M Pro Player One SDK Verified SDK properties, gain and sensor-mode checks are recorded. Fetch the SDK on your machine.
Other SDK-enumerated Player One cameras Player One SDK Supported Controls follow reported capabilities. Fetch the SDK on your machine.
ZWO EAF focuser ZWO USB SDK Supported Recorded hardware inventory identifies an EAF. The driver implements movement, position and temperature.
ZWO CAA rotator ZWO USB SDK Supported Recorded hardware inventory identifies a CAA. The driver implements rotation controls.
Wanderer Snowflake filter wheel USB serial Verified The wheel's serial protocol is recorded as checked on hardware.

Verification is limited to the check named in each row. SDK enumeration, a connected device and a completed imaging night are different evidence.

02 / ASCOM

ASCOM connections

ASCOM Alpaca

Connect compatible network devices and assign their roles. AstroDeck has adapters for cameras, mounts, focusers, filter wheels, rotators, domes, safety monitors, switches and cover calibrators.

Windows ASCOM drivers

The local COM-to-Alpaca host can expose installed Windows ASCOM drivers to AstroDeck. It requires the relevant ASCOM driver and the optional COM host dependency.

Protocol support does not verify a particular manufacturer's driver. Check the controls your device exposes.

03 / NINA

Alongside NINA

NINA's Advanced API plugin provides the connection. AstroDeck's backend exposes camera, mount, focuser, filter wheel, rotator, switch and guider roles. NINA keeps the hardware connection.

04 / ASIAIR

Alongside ASIAIR

You can use AstroDeck's planning and weather tools while ASIAIR runs the rig. An optional experimental backend also exists for ASIAIR's proprietary network protocol through libasi.

  • The backend exposes camera, mount, focuser and switch roles.
  • It does not provide filter-wheel, rotator or guider roles. Guiding remains in ASIAIR.
  • The adapter checks whether the box is busy before changing state.
  • The repository tests use a fake transport; full AstroDeck operation on an ASIAIR is not established by those tests.
  • Source installs require the asiair extra, which installs libasi from its repository.

This is not an official ASIAIR API integration. Treat the optional backend as experimental.

05 / Imaging providers

Imaging providers

Tool Requirement
Plate solving ASTAP and a compatible star database, or NINA's solver when available.
Autofocus AstroDeck native engine or a supported backend provider.
Guiding AstroDeck native engine, PHD2 or NINA's guider connection.
Polar alignment AstroDeck native engine or NINA TPPA when its prerequisites are present.

Native guiding and native autofocus require astrodeck_native, which published releases do not include yet. See issue #630 for release packaging status.
