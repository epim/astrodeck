Get started

Start with a browser and a simulated rig.

Choose a setup path, open AstroDeck locally and try a short exposure. Add real equipment after checking the drivers and imaging providers you need.

01 / Windows

Windows: run the release executable.

Open the release asset list and look for astrodeck-windows-x86_64.exe. Download the matching SHA-256 file, check the download and run the executable as your normal Windows user. It serves the browser interface without a separate Python or Node installation.

  1. Run the executable from a folder you can access. Keep its console open while AstroDeck is running.

  2. Open http://localhost:8800 on the same computer.

  3. Use the simulator steps below to try the interface.

  4. For real equipment, check the driver and provider requirements. Native guiding and native autofocus require astrodeck_native, which published releases do not include yet. Install ASTAP separately for local plate solving.

The standalone executable stores configuration and captures under %LOCALAPPDATA%\AstroDeck by default. Configuration requires NTFS or ReFS. This is a standalone executable, not a Windows installer.

02 / Simulator

Take the first exposure on a simulator.

The simulated camera responds to pointing, focus and filters. It lets you explore the workflow without connecting physical equipment.

  1. Open Equipment, or Rig > Devices in the newer interface, and choose the simulator action.

  2. Open Capture, set a short exposure and take a frame.

  3. Open Flows and inspect an example. Make a copy before changing it.

  4. Run a short plan and review its progress and frames.

Set an observing site before using visibility and scheduling tools. For a demonstration, use a location you are comfortable sharing.

03 / NINA

Connect an existing NINA setup.

Use AstroDeck's browser interface and Flows while NINA maintains the equipment connection. Available roles are listed on the hardware page.

  1. Install and enable NINA's Advanced API plugin on the computer running NINA.

  2. Connect your equipment in NINA.

  3. In AstroDeck, add a NINA driver using that computer's host and the plugin's configured port. The backend default is 1888.

  4. Assign the available NINA devices to roles and connect the rig.

Check the NINA roles

04 / Orange Pi

Orange Pi 5 Pro: distinguish Linux from appliance setup.

For an existing 64-bit Linux installation, the release workflow targets a linux-arm64 executable. Check the release assets and the device SDKs for that environment. Appliance provisioning is a separate path for a commissioned Orange Pi 5 Pro.

  1. On an already commissioned appliance, use the setup network and unique password printed for that board when an onboarding window is authorized.

  2. Connect to the AstroDeck-XXXX setup network and open http://10.42.0.1/ if the portal does not appear.

  3. Choose the home Wi-Fi network and enter its credentials.

  4. Open the appliance on the joined network using the address provided for the board.

The setup hotspot is limited to a 15-minute authorized window. There is no shared fallback password. The repository contains provisioning tooling, not a generally downloadable, ready-to-flash appliance image.

05 / Source code

Build from source when you need optional components.

A source checkout needs Python 3.11 or newer. Building the web interface uses Node 20 or newer. On Windows, these commands create an environment and install the COM host and cloudmap extras. 

git clone https://github.com/epim/astrodeck.git
cd astrodeck
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e "./server[comhost,cloudmap]"
npm --prefix ui ci
npm --prefix ui run build
.\.venv\Scripts\python.exe -m astrodeck

For AstroDeck native autofocus, guiding and polar alignment, build and install the Rust extension in the same Python environment. ASTAP and its star database are separate from that extension. The ASIAIR extra is optional and experimental.

Read the development setup

06 / Phone and tablet

Open the interface from another device.

A fresh instance binds to localhost. Create an admin account before allowing network access. The create-admin command prompts for a password and enables local sign-in. 

.\astrodeck-windows-x86_64.exe create-admin yourname
.\astrodeck-windows-x86_64.exe --host 0.0.0.0

Use the host computer's address and port 8800 from a phone or tablet on the same network. Keep the application running as a normal user.
