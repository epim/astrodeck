Astro Flows

Plan a month of imaging in an afternoon.

Planning a complicated night usually means a spreadsheet, a planetarium in another window and a lot of squinting. Draw it instead. Drag a target pool onto the canvas, wire a cloud watcher into a hold, hang a refocus off a bad frame, and the whole shape of the night sits in front of you.

The canvas

The whole night, at a glance.

Solid wires are the order things happen in. Dashed wires are what reacts when the sky misbehaves. You can read a campaign off the canvas without opening a single settings panel.

Two kinds of wire

Two wires, so you can tell plan from reflex.

Flow (solid)

This happens, then that happens

SLEW + CENTER emits centered, and AUTOFOCUS starts. Order you can see, on a canvas that will not let you draw a night with no end in it.

Event (dashed)

When this happens, do that

A graded frame, cloud arriving, a sensor going quiet: an event wire carries it to whatever should react. Events interrupt the night rather than ordering it, and a campaign that repeats for weeks is one event wire back to dusk.

A night cut short still stacks. FILTER CYCLE shoots one sub per filter per pass and repeats, so your channels grow together. Forty-five L frames and nothing else leaves you a mono image. One of each, forty-five times, leaves you a picture at every point cloud might have stopped you.

Why there are two monitors

Cloud should pause your night. Rain should end it.

Two separate blocks, because those are two different decisions. Give both jobs to one monitor and the one that ends the night wins every race, so you lose clear hours to a cloud that had already moved on.

Fail closed

SAFETY MONITOR → ABORT + PARK

Rain, wind, a sensor that stopped answering. A stale reading counts as unsafe, because "I do not know" and "it is fine" are not the same claim. The night ends, the mount parks, the dome closes.

Recoverable

CLOUD WATCH → HOLD / RESUME

Cloud is temporary and the hold releases itself. It keeps tracking, parks the guider, and on the way back it re-cools, re-centres with a plate solve and refocuses if HFR drifted. Give it a maximum hold and what to do if that expires.

Before the mount moves

Find out at your desk, not at 3am.

Press compile and AstroDeck lists every rule it cannot run, by name, with the reason. You fix it while you are awake and holding a coffee.

The failure this prevents is a quiet one. Software that silently drops settings it does not recognise will start a run that looks correct but has no dawn stop and none of the cloud rules you drew. It goes green and moves the mount, and nothing reports a problem.

So AstroDeck names what it dropped. Your cloud rule is either running or on that list.

Three shapes that cover most nights

Steal these.

Pattern

The unattended single target

DUSK → TARGET → SLEW + CENTER → AUTOFOCUS → GUIDE → FILTER CYCLE → PARK + CLOSE → REPORT, with SAFETY → ABORT hanging off the side. Eight blocks, then you go inside.

Pattern

The whole-season campaign

Swap TARGET for TARGET POOL with a quota per member, set DUSK WINDOW to repeat, and wire night ends into PARK + CLOSE. AstroDeck works the list down over weeks, taking whatever is best placed each night.

Pattern

The self-correcting night

Wire frame graded into a CONDITION set to HFR above your threshold over a 3-frame window, and fire REFOCUS. You read about the drift in the morning report instead of finding it in the stack.

Nothing here is a second code path. A flow compiles to the same sequence AstroDeck runs when you build a night by hand, so the canvas cannot grow bugs of its own.
