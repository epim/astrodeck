# Frozen release provenance review

This is a reused-context independent review of `release_provenance.py` and the frozen-artifact path in `audit_release.py`. I did not author these tools. The review read the current implementation and installed PyInstaller 6.22.3 source, then ran isolated synthetic fixtures. It did not execute an application, frozen executable, real configuration, or device operation. The gate author was notified before each mutation window; this reviewer made no gate-source edits.

Three concrete findings were reported to the author and parent. All three are now closed after independent reruns of the corrected code.

| Finding | Severity | Final disposition |
| --- | --- | --- |
| Unrecognized Python-installation files inherit verified CPython identity | High | Closed: unreviewed runtime identity, verification false |
| Code equivalence omits runtime-visible code names | Medium | Closed: independent rejection confirmed |
| Duplicate PYZ entries disappear from the member inventory | High | Closed: independent rejection confirmed |

1. `Sources.identify` accepts any unmatched path beneath `sys.base_prefix` as `component=CPython` with `record_verified=true`. A fixture patched `sys.base_prefix` to a private synthetic directory and `metadata.distributions()` to an empty list, then created `Lib/site-packages/unregistered/copied.py`. `Sources(other_repo).identify(path)` returned `python:Lib/site-packages/unregistered/copied.py`, CPython, and verified=true. Frozen review exempts CPython Python-code rows from installed-package credit/source checks. Directory placement is not evidence of CPython ownership. Excluding site-packages is necessary but insufficient for arbitrary additions under `Lib`; use a trusted per-file runtime inventory/hash source or retain an explicit unproven finding. Existing confirmed distribution RECORD entries can continue through their normal path.

2. `code_shape` includes bytecode, constants, arguments, flags, variable names and the exception table, but omits `co_name` and `co_qualname`. With a source file `VALUE = 3`, compile it, then call `code.replace(co_name='UNREVIEWED_CONTENT', co_qualname='UNREVIEWED_CONTENT')`. `code_matches(marshal.dumps(changed), source_path)` returned true. Those fields are runtime-visible identifiers and can affect introspection; they are not filename/line-table bookkeeping. Add both fields to the recursive shape and a regression that changes each independently. Ignoring filename and line information remains the documented normalization, not a claim of raw-byte identity.

3. `read_frozen` rejects duplicate CArchive names but uses the embedded reader's already-collapsed PYZ dictionary. PyInstaller's `ZlibArchiveReader` performs `dict(marshal.load(fp))`. A synthetic PYZ used two zlib-compressed marshaled code objects, one containing `HIDDEN = 'synthetic uninspected payload'` and the other `VISIBLE = 1`. Its raw TOC was `[('duplicate', (0, 12, len(first))), ('duplicate', (0, 12 + len(first), len(last)))]`. The header was `b'PYZ\0' + importlib.util.MAGIC_NUMBER + struct.pack('!i', 12 + len(first) + len(last))`, followed by those blobs and the marshaled TOC. A `CArchiveWriter` wrapped it as `('PYZ.pyz', path, False, 'z')`. The collector accepted the archive and enumerated only `PYZ.pyz!/duplicate` once. The first physical payload was uninspected. Matching the container to a retained build file does not account for those hidden bytes, especially since the collector promotes archive-container matches to verified status. Validate the raw PYZ TOC before dictionary construction; reject duplicate names, invalid ranges and unexplained payload regions rather than letting nested bytes inherit container classification.

The Windows envelope reconstruction is stronger than an observed-prefix hash: it requires the supported PyInstaller version and options, installed RECORD ownership for the precise console bootloader/icon, the expected manifest, exact retained PKG bytes without a suffix, and byte-for-byte equality after the reviewed resource/timestamp/checksum transforms. The code does not claim equivalent reconstruction on other platforms. I found no concrete prefix-tampering acceptance in this read-only review. The installed upstream `_GUTS` ordering matches the indexed fields used for the Windows checks.

The new native/source/notice paths are collected through actual metadata members. The narrow PEP 610 privacy follow-up excludes only each server/native metadata directory's root `direct_url.json` from the frozen payload. It retains RECORD, every license/source/SBOM member and nested files. This separate packaging fix has 71 green tests and 43 assertion-specific mutants with exact source restoration; the final frozen artifact still needs rebuilding after rebase. RECORD may describe installed files omitted from a frozen subset, so frozen subset validation should not apply the wheel's exact RECORD-coverage rule to that subset.

The supplied JSON provenance remains build evidence, not a signed external attestation. The gate checks artifact and collector hashes but trusts the collector report's recorded properties; the workflow must continue to generate it from the current retained build inputs. Current runtime/library and owner blockers must not be cleared solely because the same bytes were seen in an older artifact. This reviewer has not claimed a hosted four-platform build or release clearance.

Independent final verification: the unregistered site-package now returns `runtime-unreviewed:Lib/site-packages/unregistered/copied.py`, `component=Unreviewed runtime input`, and `record_verified=false`. Changing either `co_name` or `co_qualname` independently now makes `code_matches` return false. A canonical 17-byte-header PYZ control enumerates its one module successfully; the same fixture with duplicate module names is rejected as `duplicate or invalid PYZ member name`. The full restored release-gate suite passed 62 tests in this reviewer's run. The author separately reports 23 named mutants killed and exact source restoration.

No remaining confirmed false-clear finding is open from this review. This closes the three specific reproductions; it does not certify a hosted build, a newly rebased artifact, or unreviewed runtime bytes.
