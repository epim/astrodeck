# Reused-context independent review of root release work

I did not author the root-owned release workflow or relay checker. This review reuses the ongoing task context; it is not a fresh-context review. Read-only source review and isolated synthetic fixtures were used. No Docker daemon, image build, deployment, real config or hardware was contacted.

Two reproducible false accepts were found and are now closed after independent reruns in `deploy/reverse-proxy/check_build_contexts.py` and reported to the parent for correction:

1. Medium: Python `fnmatch` treats `*` as matching path separators. In a fresh context with `relay/deep/private.py`, `.dockerignore` containing `*` followed by `!relay/*.py`, and `COPY relay/deep/private.py /payload`, `check_build` returns `([], ['relay/deep/private.py'])`. Docker's separator-aware matching leaves that nested file excluded. A negation rule must not re-include it by crossing `/`. Use a segment-aware matcher or reject unsupported patterns.
2. Medium: `Path.glob` gives `**` recursive and zero-directory behavior to COPY operands. In a context containing only `relay/top.py`, `COPY relay/**/*.py /payload` returns `([], ['relay/top.py'])`. COPY wildcard matching follows Go `filepath.Match`; Dockerignore's special recursive `**` does not apply to COPY. Reject COPY double-star and unsupported character classes unless their distinct grammar is implemented.

The reproduction imports the checker by path, creates the described files beneath a unique `.probe/release/review-relay-*` temporary directory, calls `check_build(Build('fixture', context, context / 'Dockerfile'))`, and prints the returned findings and inputs. Both observed results above were executed, not inferred from inspection. The expected semantics are supported by the [Docker COPY reference](https://docs.docker.com/reference/dockerfile/#copy), [Dockerignore syntax](https://docs.docker.com/build/concepts/context/#dockerignore-files), and [Go filepath.Match grammar](https://pkg.go.dev/path/filepath#Match).

After the parent correction, the first exact reproduction returns `COPY source is excluded by dockerignore: relay/deep/private.py`; the second returns `unsupported recursive path pattern`. All 14 relay regression tests pass in this reviewer's independent run. The corrected matcher uses segment-aware patterns, rejects unsupported COPY recursive/class/backslash syntax, and filters host case-insensitive glob matches.

A directory operand is currently tested only at its top directory. The checker does not inventory its included descendants or prove required runtime files survived ignore rules. This should remain an explicit coverage limit unless descendant traversal is added. It is not evidence that a full container image runs.

The release workflow separates build jobs from the publishing job. The publisher depends on the source and all binary jobs, downloads accepted artifacts only, signs the tar and checksums the four wheels plus four executables. The wheel is installed before fresh credits/UI generation, and the frozen builder's mandatory native probe runs even when server smoke is explicitly skipped locally. The workflow leaves owner decisions pending rather than widening redistribution permission. The retained image job is downstream of publishing, with the container-native/inventory gap explicitly tracked as #655. No additional workflow blocker was established in this source review. Parent's workflow tests and actionlint evidence are separate from this review; this reviewer has not run the hosted matrix.

The scoped existing fixtures ran with `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`, `pytest --noconftest -o addopts=`, and exactly the binary smoke, build_release, build_release_workflow, licence_artifact, licence_dependencies and licence_frozen test files: 81 passed, one fixture failed. The failing fixture copies only build_release.py into a synthetic repository; it must also copy the new central policy loader and JSON. This needs the approved existing-test exception and is not a reason to weaken the actual artifact policy. The parent was also warned that the old workflow-command scanner misclassifies an explicit test_build_release.py argument in YAML as a builder invocation; a scoped shell glob avoids that collision.
