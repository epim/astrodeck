# Gallery review and capture geometry warnings

Reviewed against `0f41ef87` on 2026-09-19, in the isolated `codex/issue77-capture-geometry` worktree. All fixtures were synthetic. No production capture, mount, sequence, or deployment operations were performed.

## Result

The gallery's existing filtering, night boundaries, previews, downloads, trash, and access checks passed the targeted regression suites. It is not yet consistently fast or stable under a changing large library: three separate issues remain open below.

This change addresses [#77](https://github.com/epim/astrodeck/issues/77), plus two defects found during this review. It has not been pushed or deployed.

## Included fixes

### Mixed capture settings: #77

- Read actual width, height, horizontal/vertical binning, and exposure from FITS headers. Invalid or absent values remain unknown. Zero-second bias exposures remain valid.
- Return capture-group counts for the entire filtered library, including frames beyond the first page. Groups separate targets, filters, frame types, dimensions, binning, and exposure.
- Show these groups in the classic Gallery and the session Files sheet. A mixed-settings notice remains visible while details are collapsed. The expanded list renders 40 groups at a time; the server bounds the response at 1,000 groups and explicitly marks truncation.
- Warn in flow compilation and in the sequence night log when planned light settings differ from the largest saved group, when mixed groups already exist, or when relevant metadata is incomplete. These warnings allow capture to continue.
- Compare output dimensions at capture boundaries and report a new size once per target/filter/settings/size combination. This comparison uses local linear image data; a bridge's resized preview is not treated as the saved FITS geometry. Saved FITS dimensions remain available in the gallery.
- Do not infer output dimensions by dividing sensor size by binning. Some cameras trim their output, so this would produce false warnings.
- Stop displaying a median exposure as though all files share it. For library-only Files rows, sum the actual exposures for integration time.

#### Performance and limits

Geometry checks share one background inventory scan. Compiles wait at most one second; sequence startup waits at most three seconds. A timeout produces an explicit incomplete-check warning. If the startup scan finishes later, a capture boundary reads that same result and logs the warnings. It does not start a new scan per exposure.

Completed inventories are reused for five seconds. The scan inherits the existing gallery file ceiling and announces incomplete coverage when that ceiling is reached. A step with an unspecified filter means “keep the current wheel position”; it is not guessed to match any named filter in the library. Target/filter matching ignores case and surrounding whitespace, but does not resolve catalog aliases. These checks are advisories, not a guarantee that a calibration library is compatible: camera identity, gain, offset, temperature, and other calibration requirements are outside #77's geometry key.

Grouping 5,002 synthetic frames took a median **7.7 ms** over five runs on the development PC. This is grouping overhead, not an end-to-end gallery latency claim or a Raspberry Pi benchmark.

### Invalid FITS exposure values: #82

[Issue #82](https://github.com/epim/astrodeck/issues/82): an EXPTIME card containing `NaN` or infinity became a non-finite Python float, which the API's JSON serializer rejects. The reader now validates exposure independently, returns null for invalid values, and still reads valid dimensions and timestamps. API regressions exercise non-finite strings, malformed strings, and negative exposure values.

### Preview error overlap: #83

[Issue #83](https://github.com/epim/astrodeck/issues/83): the picture-placeholder icon remained behind the failed-preview explanation. The placeholder is now hidden when a failure message is displayed. Download and selection controls retain their existing behavior.
