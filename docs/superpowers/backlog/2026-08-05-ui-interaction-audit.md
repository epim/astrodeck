# UI interaction-state audit (2026-08-05)

Produced by a 112-agent pass over every AstroDeck screen: 16 reviewers against a
fixed interaction-truth rubric, then EVERY candidate finding attacked by an
independent verifier told to refute it. 95 candidates -> 88 confirmed,
7 refuted. The refuted ones are correctly absent.

The question behind the rubric: **does a control tell the truth about what it is
doing, and about what the hardware is doing?** In an ordinary web app that is a
UX concern. In a telescope controller, where a button starts physical motion
that outlives the HTTP response, it is a safety concern.

All three hazards were re-verified BY HAND against the source before this file
was written -- they are not taken on an agent's word. Two of them are worth
stating up front because they invert the usual severity intuition:

* the polar Pause hazard is partly a CONSEQUENCE of the server-side pause fix
  shipped in 0.2.44 the same night: suppressing the driver's late "running"
  stopped the pause being overwritten, but it also removed the flicker that used
  to (accidentally) tell the operator the mount had not stopped yet;
* the sun-avoidance toggle keeps its optimistic value on a FAILED write on
  purpose, with a comment explaining why -- reasoning that is correct for a text
  draft and wrong for a hazard interlock.

# AstroDeck UI Interaction-State Audit — Final Report

88 findings survived adversarial verification. 3 hazard, 27 high, 50 medium, 8 low.

---

## 1. THE HEADLINE

**Three controls can leave the telescope moving while the screen says it has stopped, or leave the only stop control inert.**

- **The slew pad destroys its own buttons every 2 seconds.** `Arrow` is declared inside `SlewPad`'s render body, so every telemetry tick (and the press itself, at the two continuous rates) gives it a new component identity and React deletes and recreates all four `<button>` nodes. That implicitly releases pointer capture, and the `onLostPointerCapture` force-stop is dispatched at a detached node React can no longer route. Press and hold N, slide a thumb a few millimetres off the 56 px button in the dark, lift — the mount keeps slewing at the commanded rate and all four arrows reject every further press because `activePointerId` is never cleared. Only the red STOP bar recovers it. Keyboard and switch users can never hold focus on an arrow either, because the focused node is destroyed on every tick. `SlewPad.tsx:271`
- **Polar align's Pause announces a stop that has not happened.** The chip, the reticle caption and the button all flip to "paused" the instant the POST returns, and `session.py` then actively suppresses any later `running` so the display cannot self-correct. The pause flag is only observed *between* rotations; an in-flight 12° RA slew has no abort path and runs another 5–15 seconds. This screen's own comment describes the workflow as "crouched at the mount... turning a bolt with the other." It invites hands onto an unbraked AM5 that is still swinging, and the only motion truth anywhere is a header chip hidden below 768 px. Note the inversion: the adjacent, gentler-looking Stop *does* halt the mount promptly. `PolarView.tsx:267`
- **Re-arming sun avoidance claims success on a refused write.** The toggle is optimistic and the catch never reverts: the switch snaps ON, the red SUN AVOIDANCE OFF banner disappears, the badge goes green "Armed" — while the server still permits a slew at the Sun. `SafetyPanel.tsx` is the only surface in the entire UI that renders this interlock, so nothing can contradict it, and the reseed effect keys on primitives the failed write left unchanged, so it never self-corrects. Fails in the dangerous direction on a control whose own file header describes it as protecting against destroying the camera and blinding anyone at the eyepiece. `SafetyPanel.tsx:234`

**Then the systemic part — two-thirds of this report is three mechanical mistakes repeated across every screen.**

**(a) The server's `_spawn` returns `{"started": name}` the moment a background task is created, and 20 controls read that 200 as "the operation finished."** Solve & Sync, GOTO, Park, Close roof now, Upgrade, Activate profile, Force Recalibrate, sequence Pause, Monitor Pause, polar Start. The device truth these controls need is already on the wire and already typed: `status.busy` (from `hub.busy_label`, `types.ts:163`) is published on every 2 s status frame and is read by exactly **one line in the whole UI** — `ws.ts:180`, for stale-banner suppression. One `useBusy(lane)` selector wired into those controls closes most of class D at once.

**(b) 17 controls have no in-flight state at all**, and because most sit on `_spawn` lanes that refuse duplicates, the retry this invites returns the raw internal lane name as a red error toast: `'goto' is already running`, `'solve' is already running`, `'guide_assistant' is already running`, `'system.update' is already running`. Two shared fixes: an in-flight guard on the control, and one branch in `lib/apiError.ts` / `lib/humanize.ts` so a lane name never reaches a human.

**(c) The repo wrote the honest-disabled rule itself** — `ui.tsx:601-644` §11.8, `HonestButton`/`LockedChip`/`LockedNote`, applied correctly in ~15 components — **and then broke it in 8 places** with a bare native `disabled` plus `title=`, which never fires on the tablet this rig is driven from.

Nearly every "wrong value" defect in this report also has its correct implementation somewhere else in this same codebase. `PowerView`'s `drafts[id] ?? p.value` reconcile, `SitePanel`'s primitive-keyed reseed with its explanatory eslint-disable, `GalleryView`'s generation guard, `CaptureView`'s "arm only after the server accepts." The fixes are mostly *applying idioms already present*, not inventing new ones.

## 2. SYSTEMIC PATTERNS

### D — Reports the request, not the effect (20 findings) — largest group, one shared fix
`_spawn` returns immediately; local `busy` clears in a `finally`; the label reverts while the mount slews, the camera exposes, or the roof is still shut. **Shared fix:** drive label/`disabled`/`aria-busy` from `status.busy` (or `mount.slewing`, `guide.phase`) OR'd with a local flag that covers only the request gap. Covers findings on `MountView.tsx:220/300/191`, `AtlasView.tsx:742`, `SequenceView.tsx:581`, `MonitorView.tsx:583`, `PolarView.tsx:258/267`, `GuideView.tsx:130/134/236`, `SafetyPanel.tsx:184`, `UpdatePanel.tsx:117`, `EquipmentView.tsx:624`, `ProfileList.tsx:125`.
**Sub-pattern with teeth (`replace=True` lanes):** Park, Close roof now, and Force Recalibrate re-post into lanes that *cancel the in-flight work*, so the retry an idle-looking button invites actually restarts a minutes-long operation. These three must be hard-disabled while the lane is busy, not just relabelled.
**One-offs inside D** (separate patches): FocusView Halt clearing the narration before the POST (`1129`), FocusView presets lighting without sending (`328`), GuideView assistant Stop's empty catch (`834`), GuideView Stop's single-fact gate (`134`), Radar refresh's quantized no-op (`RadarMap.tsx:334`).

### H — A value that is never invalidated (21 findings) — four sub-patterns, four shared fixes
1. **Local draft outranks device truth and never reconciles** (9): dew heater `CaptureView.tsx:1299`, cooler target `:142`, exposure clock `:428`, dew slider `PowerView.tsx:170`, match-camera lock `AtlasView.tsx:538`, HFR chip `PreviewStage.tsx:705`, focus narration `FocusView.tsx:288`, calibration panel `GuideView.tsx:156`, assistant run `GuideView.tsx:770`. **Shared fix:** `PowerView`'s `drafts[id] ?? server.value` reconcile, plus retiring the draft on the event that supersedes it.
2. **Snapshot at mount, never refreshed** (6): roof badge `SafetyPanel.tsx:83`, factory-reset gate `FactoryResetPanel.tsx:154`, ACTIVE badge `ProfileList.tsx:127`, per-row connect errors `EquipmentView.tsx:1119`, "rig connected" from localStorage `EquipmentView.tsx:182`, driver list after a partial batch `DriversPanel.tsx:91`. **Shared fix:** refetch on the event that changes it (`MonitorView.tsx:275` already polls the identical dome route every 15 s with a comment explaining why).
3. **Store push destroys deliberate local edits — the inverse staleness** (2, plus a named third): `OpticsPanel.tsx:103`, `SafetyLimitsPanel.tsx:111`, and `EscalationPanel.tsx:90` has the identical shape. **Shared fix:** key reseed effects on a primitive signature exactly as `SitePanel.tsx:124` already does.
4. **Genuine one-offs** (4): `update` WS frame dropping `can_apply` (`UpdatePanel.tsx:213` — server-side `snapshot()` fix), Gallery "Load more" with no generation guard (`GalleryView.tsx:238`), downloads offered for server-freed frames (`PreviewToolbar.tsx:263`), stale visibility night (`AtlasView.tsx:560`).

### B — No in-flight state at all (17 findings) — shared fix
A busy flag plus `disabled`/`aria-busy` on the control. The codebase already does this correctly in `CaptureView`, `SitePanel.run()`, `ProfileList.setBusyId`. Sites: `MountView.tsx:167/300`, `AtlasView.tsx:391`, `FocusView.tsx:640`, `SequenceView.tsx:590/632`, `PlanLibraryPanel.tsx:222`, `GuideView.tsx:464`, `EquipmentView.tsx:553`, `ProfileList.tsx:107`, `SitePanel.tsx:284/348`, `ReportView.tsx:411/427/449`, `PowerView.tsx:118`, and one call-site omission in `MountView` (not a primitive gap — see What Is Already Right).
Two carry extra damage beyond the missing spinner: Guide Tuning (`GuideView.tsx:464`) clobbers persisted per-axis params on **every** open-and-save, and Plan Save (`PlanLibraryPanel.tsx:222`) can mint duplicate plans.

### I — False confirmation (8 findings) — shared principle, per-site patches
Claim only what the response says; revert optimistic writes on rejection. Both safety-tier instances are in one file (`SafetyPanel.tsx:234` hazard, `:169` high) and share a `persistFlag` helper fix. The rest: `PlanLibraryPanel.tsx:181` (export toast fires outside any try), `GuideView.tsx:866` (ignores the `{cleared}` flag the server returns — and the correct implementation is 200 lines up at `:657`), `PolarView.tsx:274` (success gated on state string, not error magnitude), `UsersPanel.tsx:192`, `SitePanel.tsx:259`, `TouchGuard.tsx:358` (haptic confirmation fired *before* the POST leaves).

### G — Silent disable, reason unreachable (7 findings) — pure mechanical sweep
Bare native `disabled` (or dimming without `pointer-events`) with `title=` as the only reason channel, on the tablet where `title` never fires. `FilterNamesModal.tsx:326`, `FocusView.tsx:973`, `SequenceView.tsx:811`, `PolarView.tsx:269`, `RadarMap.tsx:344`, `PreviewToolbar.tsx:349`, `SafetyPanel.tsx:318`. **Shared fix:** convert to `HonestButton`/`LockedChip`/`LockedNote`; the `PreviewToolbar` one needs only the `onBlocked` prop the primitive already declares and both `CaptureView` call sites already pass. Every one of these is a deviation from a rule this repo wrote down, not a missing convention.

### J — The control misdescribes itself (6 findings) — mostly one-offs
`MountView.tsx:221` (one shared `busy` puts "Solving…" on non-solves while the real solve reads idle — an inverted label), `guideNarration.ts:59` ("trying to recover" shown only when nothing is recovering, and it survives Stop), `EquipmentView.tsx:1196` (`aria-disabled` announced to assistive tech on a fully working button, with no dimming — invisible to screenshot review), `PreviewToolbar.tsx:381` (`role="menu"` with no keyboard model, non-menuitem children, and the only popover Escape won't close), `AlertsPanel.tsx:444` (a global lock dims one row and silently no-ops the others), `ui.tsx:281` (HoldButton's armed caption). Only the last shares a file with another finding.

### C — A latch that never clears (3 findings)
Every exit path must emit or reset. `slewController.ts:196` (the one exit that never calls `emit()`), `SlewPad.tsx:194` (force-stop without clearing `activePointerId`), `UsersPanel.tsx:384` (`setBusy` with no `finally`). Same principle, three separate patches.

### E — The gesture is ended by lifecycle or wall clock, not by the user (2 findings)
`SlewPad.tsx:271` (hazard, above) and `ui.tsx:295` — HoldButton banks `performance.now()` from pointerdown, so a hold interrupted by a hide that delivers neither pointerup nor pointercancel, or by any main-thread stall longer than `holdMs`, completes itself with nothing on the glass. Independent fixes, but note the guard HoldButton needs already exists at `SlewPad.tsx:173-188`, and HoldButton's own keyboard path already disarms on a timer — the project applied its own safety standard to the sibling control and the sibling code path, and skipped the pointer path of the shared primitive.

### F — Re-entrancy guard set too late (2 findings)
`AtlasView.tsx:701` (guard set after two awaits) and `FocusView.tsx:336` (arms `cmd` before the POST, and clears it unconditionally on any rejection). Both are one-line moves; `FocusView` should adopt `CaptureView.tsx:317-330`'s documented rule — arm only after the server accepts, so a rejected request cannot stomp a genuinely running operation.

### A — The control cannot be pressed at all (2 findings) — both in the preview stage
`StretchHistogram.tsx:189`: the pointer handlers live on the `<svg>`, the three handle boxes are later absolutely-positioned siblings, so each 32 px handle is a **dead column centred on its own level line** — the file header's promised "hit slop" is exactly the dead zone. `PreviewStage.tsx:775`: the gesture layer's `setPointerCapture` retargets pointerup to the stage div, so no explanation chip inside the stage can ever be tapped, and the chip's own pointerdown stamps a timestamp that closes the focus fallback too; the natural double-tap retry zooms the preview to 100%. **Shared fix:** `data-no-pan` — the one working precedent, `StarOverlay.tsx:87` (its accompanying `stopPropagation` is inert; only the attribute is load-bearing).

## 4. WHAT IS ALREADY RIGHT

**The server is the adult in the room.** Not one "double-fire" finding in this report can actually start two operations. `_spawn`'s check-and-register is synchronous with no await between the two, so the second POST is deterministically refused — every double-fire here is a *feedback* defect, not a control defect. `close_observatory` re-verifies the mount is parked and refuses to move the roof over an unparked scope, which is the only reason the "Close roof now" restart is high and not hazard. `apply_preconditions` re-gates the updater server-side, which is the only reason the clobbered `can_apply` cannot interrupt an exposure. `hub.connect_rigspec` serializes on `_connect_lock`, so a mid-activation Connect queues rather than races.

**Primitives carrying their weight.** `HonestButton`/`LockedChip`/`LockedNote` are used correctly in ~15 components — every G finding is a deviation from a rule this repo wrote for itself at `ui.tsx:601-644`, not a missing convention. `Toggle` already exposes an in-flight channel through `disabled`, and ~28 of ~30 call sites thread `busy` into it (including both sites originally filed as counter-examples); finding 88 is a single call-site omission, and the "gap multiplies through the primitive" thesis is inverted. `PickerButton` declares `onBlocked` and both `CaptureView` call sites wire it. `pushConfirm` is a replace-and-cancel singleton, which is what refuted a candidate stacked-slew finding outright. `Panel`/`Field`/`Stat` are honest dumb wrappers that never pretend to supply state.

**Idioms that already exist and just need spreading.** `PowerView.tsx:141/170-171` (server value wins when idle; commit on pointerup *and* keyup) is the correct answer to five stale-draft findings. `SitePanel.tsx:124` (primitive-keyed reseed with an eslint-disable and a comment explaining why) is the correct answer to the whole reseed-clobber group. `GalleryView.tsx:106-154` guards three of its four fetches, and `SitePanel`'s sky-hint effect carries a `dead` flag — the generation-guard pattern is native to this codebase. `CaptureView.tsx:317-330` documents "arm only after the server accepts, so a rejected request cannot stomp a genuinely-running frame," which is exactly the fix `FocusView` needs. `ProfileList.tsx:310-327` does the export-download correctly, and `:205-220` re-lists from the server before choosing a confirm's severity — the mitigation the display side of that same file lacks.

**Copy quality, where it exists, is genuinely good.** `SafetyLimitsPanel`'s "Stop starting new frames" is the honest phrasing sequence Pause needs. `atlasFov.ts:364` — "this follows the mount's reported position, so it reaches the target only when the mount does" — states the truth the GOTO buttons omit. `FocusView.tsx:357-362` forbids native `disabled` with a stated reason. `PreviewToolbar`'s file header names the exact failure `LockedChip` exists to prevent. `RadarMap`'s own R2-WEA-04 rationale says "a blank layer must never read as clear sky." The defects cluster in the places that did not use the house standard.

**Clean areas.** No finding touched captured data: the imaging pipeline, session store, frame records and the 30-day recoverable trash were not implicated, and no finding can command wrong hardware motion. The sequence engine's session/resume model, the WS store's event fan-out (except the one partial-payload clobber on the `update` channel, which `hub.py:1446` shows was already fixed once for `safety`), and the RBAC/redaction layer held up under probing. 7 candidates were refuted and the refutations were substantive rather than technicalities.
