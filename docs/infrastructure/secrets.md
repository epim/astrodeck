# Secrets Inventory

Every secret in the AstroDeck stack: what it is, where the **source of truth**
lives, where copies live, and how to rotate it.

## The write-only rule (read this first)

**GitHub Actions secrets cannot be read back.** The GitHub UI and API only ever
tell you a secret *exists*, never its value. A workflow can *use* a secret, but
nobody — not you, not an admin — can retrieve the stored value afterward.

Consequences:

- The **source of truth** for every secret is your **password manager** (and/or
  the upstream system that issued it, e.g. Fly). GitHub holds a *copy* you can
  overwrite but not read.
- "How do I get the secret out of GitHub?" → **you don't.** If you've lost it,
  **rotate**: mint a new value upstream, then overwrite the GitHub secret
  (`gh secret set NAME` or Settings → Secrets and variables → Actions).
- Set a secret without it landing in shell history or argv:
  ```
  gh secret set NAME --repo <owner>/<repo>      # then paste the value at the prompt (stdin)
  ```

## Inventory

### `FLY_API_TOKEN` — relay auto-deploy
- **What:** a Fly.io deploy token authorizing `flyctl deploy` for the relay app.
- **Source of truth:** Fly (`fly tokens create deploy`) + your password manager.
- **Copies:** GitHub Actions secret `FLY_API_TOKEN` (used by `deploy-relay.yml`).
- **Rotate:** `fly tokens revoke <id>` (old) → `fly tokens create deploy` (new) →
  `gh secret set FLY_API_TOKEN`. Nothing else references it.
- **Blast radius if leaked:** deploy access to the relay app only (scope this
  token to the relay app, not org-wide).

### `RELEASE_SIGNING_KEY` — release signing (Ed25519 private seed)
- **What:** the base64 32-byte Ed25519 **private seed** that signs release
  artifacts. The matching **public** key is pinned on every scope.
- **Source of truth:** your password manager. Generated by
  `python scripts/gen_signing_key.py`.
- **Copies:** GitHub Actions secret `RELEASE_SIGNING_KEY` (used by `release.yml`'s
  sign step).
- **Rotate:** generate a new pair → `gh secret set RELEASE_SIGNING_KEY` → update
  the pinned **public** key on every scope (Settings → Updates) **before** cutting
  the next release. A release signed with the new key will not verify against an
  old pinned public key (fail-closed, by design).
- **Blast radius if leaked:** an attacker could sign a malicious release that
  scopes would accept. Rotate immediately and re-pin public keys.

### Relay **device tokens** — home ↔ relay pairing
- **What:** one high-entropy token per scope/home, shared between the relay and
  that home; maps the home to a stable `home_id`.
- **Source of truth:** your password manager. Generated with
  `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
- **Copies:** on the **relay** as a *mounted file* (`RELAY_DEVICE_TOKENS_FILE`,
  JSON `{token: home_id}`); on the **home** in `RemoteConfig.device_token`
  (scrubbed from any API/WS payload by `redacted()`).
- **Rotate:** generate a new token → update the relay's token map file →
  update the home's `RemoteConfig.device_token` → the home reconnects. A higher
  `generation` on reconnect fences the old scope connection.

### Relay **Ed25519 seeds** — reserved OIDC + viewer-link signing
- **What:** two separate 32-byte Ed25519 seeds the relay uses to sign (a) OIDC
  session material and (b) revocable viewer links if those optional components
  are enabled. The currently exposed relay routes do not use either signer. The
  home holds only the matching **public** keys (`relay_pubkey` /
  `viewer_link_pubkey`).
- **Source of truth:** your password manager.
- **Copies:** on the relay as *mounted files* (`RELAY_OIDC_SEED_FILE`,
  `RELAY_VIEWER_SEED_FILE`); the public keys are configured on the home.
- **Rotate:** mount new seeds on the relay, load the new public keys on the home.
  Without a seed the corresponding signer is disabled and fails closed. Runtime
  startup never falls back to the unit-test-only development HMAC signer.

### Optional / app-level secrets
- **`ASTRODECK_TOKEN`** — optional break-glass shared bearer token (off by
  default; setting it requires that token for LAN access). Env var on the scope.
- **`ASTRODECK_SECRET`** — session-signing secret. If unset while an auth method
  is enabled, the server auto-generates and persists a random one; set it
  yourself to manage the key. Env var / persisted file on the scope.
- **Alert sink tokens** (e.g. a Telegram bot token) — stored in the scope's
  config, blanked from any outbound payload by `ConfigStore.redacted()`.

## Quick rotation checklist

| Secret | Mint new | Update copies |
|--------|----------|---------------|
| `FLY_API_TOKEN` | `fly tokens create deploy` | `gh secret set FLY_API_TOKEN` |
| `RELEASE_SIGNING_KEY` | `scripts/gen_signing_key.py` | `gh secret set RELEASE_SIGNING_KEY` **+ re-pin public key on every scope** |
| relay device token | `secrets.token_urlsafe(32)` | relay token map file **+** home `RemoteConfig.device_token` |
| relay OIDC/viewer seed (if enabled) | new 32-byte seed | relay mounted files **+** home public keys |
