AstroDeck · Program Design Spec · 2026-06-16

Your rig.
Your rules.
No vendor.

An open, vendor-neutral controller for a telescope rig — an ASIAIR you actually own. Four workstreams: a pluggable backend harness, capability-based RBAC, a dial-out cloud relay, and native drivers.

The lock-in

A closed appliance decides which mounts, cameras and guiders you may use. Swap a vendor and you swap your whole controller. The astro stack is fragmented — ASCOM, Alpaca, INDI, NINA — and most tools marry exactly one.

The answer

Make backend choice DATA, not an if/elif chain. A Backend + BackendSession plugin seam, a registry, and a per-rig plan. NINA is a transition bridge; the end-state is no-NINA via Alpaca + native drivers.

The discipline

Every workstream is specced → built → verified in dependency order, each stage ending green on pytest + npm build. In-process fakes, not mocks. Safety holes are closed at the boundary, not papered over with banners.

Dependency order W1 the seam → W2 roles to enforce → W3 remote access that tags an authenticated role → W4 drivers, which are just more registrations. You can't ship remote access before there are roles to enforce over it.
W1 · The plugin seam

A new backend is a new file
and one register() call.

The contract lives in devices/backend.py — already committed and canonical. A backend is a stateless factory; open() makes a session: one live transport that hands out a device per role. The hub never names a backend — it iterates the registry and the active plan.

The four contract types

  • ConnSpec — how to reach ONE role on ONE backend. The persisted, replayable unit. Optional fields default to None (not ""/0) so an absent host/port is unambiguous across to_dict/from_dict.
  • RigSpec — a whole rig: a primary backend + per-role ConnSpec overrides. resolve(role) falls back to the primary.
  • Backend — a registered KIND (factory). Carries name, label, roles, discoverable, and hostless — the flag that coalesces endpoint-less backends (sim, PHD2-local) to one session.
  • BackendSession — a live opened connection. get_device · native_guider · native_solver · guide_camera · health · close. The hub may read only these Protocol members.

The registry diagram

Honest cost "Zero hub edits" is literally true of hub.py — and scoped to new backends filling existing roles. A genuinely new backend still adds one from . import X_backend line to backends/__init__.py (a deliberate, ordered, debuggable registration site). A brand-new role is a known multi-file change.
W1 · Primary + per-role overrides

Pick a primary.
Override one role.

The user picks a primary backend that fills every role by default, then optionally overrides individual roles. The guider being independently pluggable today is exactly this model with one override — W1 generalizes it to all roles.

Mixed-rig role map

Per-role REAL/SIM is the operator truth

A primary=sim rig with a real-mount override must not show a global "simulator" chip while a real mount physically slews — a dangerous lie on the daytime bench. So every place the operator acts reads its own role's backend: the Mount view + SlewPad, the capture controls, and the guide controls each carry a persistent REAL/SIM and NINA·native·PHD2 badge.

Saturated motion-class warning

A header banner that names the real role, loudly: "REAL MOUNT (native) — motion is physical." A mostly-sim bench rig with one real motion device is never mistaken for pure sim.

First-motion "arm" gate

The connect confirm is one-time; the fake-solve-then-slew hazard recurs. So an Arm real mount toggle gates the pad before any press — never a modal fired from inside onPointerDown (which would steal pointer capture mid-press and strand a runaway slew).

Solve & Sync, explained at the control

On a real mount + sim camera the button is disabled-with-explanation — and the PreflightModal pins a blocker row so a centering sequence can't start a silent per-target refusal mid-run.

Banner precedence — one loud region
REAL-MOTION› DAYTIME/SUN› PAUSED-PENDING-ACK› boot-failure› transport-down› telemetry-stale
At most one loud banner shows; the rest collapse into the header chip cluster. Safety banners stay distinguishable by icon/shape/letter, not hue — red-on-red is invisible in the dark.
W1 · The orchestrator

One function brings a rig online.

connect_profile(spec) → ConnectResult — a deliberate rename + reshape of the committed assemble()/AssembledRig, with the shipped tests carried forward as the gate that proves the reshape is non-regressive. It owns role→backend resolution, one session per endpoint, graceful per-role degradation, and teardown-on-partial-failure.

The tri-state result, per requested role

A dict of failures can't tell never-tried from failed from connected. So every requested role gets one RoleResult(role, ok, error, attempted) — the basis for the LED grid.

attempted=false · never tried attempted · failed (error inline) ok · connected

_requested_roles(spec) = set(spec.roles) ∪ get_backend(spec.primary).roles. An unfillable role on a given rig gets no LED — never a permanent red.

Grouping & degrade rules

  • Key by (backend, host, port) — a native rig can split mount and camera across two Alpaca hosts; each endpoint opens exactly one session.
  • Hostless backends normalize host/port → None via the Backend.hostless flag (never a literal {sim, phd2} name set), so all sim roles coalesce to one SimRig even with stray addressing.
  • Per-role failure degrades to "disconnected" — a missing focuser must not stop the camera coming up.
  • Close-before-open on re-apply + teardown on any raise, so two generations of transports never coexist and leak across a profile switch.
Two subtle correctness pins The back-compat to_dict["sessions"] must stringify the new tuple keys and sort None-safely — sorted(str(k) for k in result.sessions) — or two same-host endpoints of differing port-presence crash on int < None. And _pick_guider/_pick_solver must key sessions through the same hostless-normalized key _group used, or a stray-addressed sim/PHD2 guider override goes missing as a spurious "no guider."

Boot auto-connect & graceful degrade

Failure-swallowing boot

On startup, if a profile is active, build its RigSpec and connect best-effort. A raise inside _lifespan bricks the whole UI — so failures are swallowed, the app starts, and /api/status returns 200 with the rig marked disconnected.

Mount posture: never initiate

AstroDeck never auto-unparks, auto-slews, or enables tracking without an authenticated human action. A mount that comes online idle is left PARKED with tracking OFF.

…but it DOES halt unsafe motion it finds

A real mount discovered unparked + tracking into the sun cone is STOPPED (optionally PARKED) BEFORE any banner — a deliberate exception to "never initiate."

PAUSED-PENDING-ACK A persisted in-progress sequence is never auto-resumed across a restart. It enters a distinct held state — "Held after restart — no motion until you resume" — surfaced on the header chip and the escalation sink. Resume is a consequence-naming hold-confirm ("re-slews the mount and may perform a meridian flip") that re-runs the sun-cone check on the first re-slew. Unattended boot defaults to no motion until acked — by design.
W1.7 · Managed PHD2

AstroDeck owns PHD2 as a
supervised internal service.

The complaint: NINA shells out to phd2.exe and you hand-maintain a separate PHD2 equipment profile. AstroDeck's answer — behind the same Guider interface — is a ManagedPhd2 supervisor when conn.extra["managed"] is set.

The supervised lifecycle

  • 1Auto-launch phd2 --headless with shell=False and a fixed argv list — never a shell string.
  • 2Sync the profile on disk — PHD2's JSON-RPC cannot set the camera/mount driver, pixel scale or focal length, so AstroDeck writes the platform store directly (Windows registry / PHDGuidingV2 INI) via a Phd2ProfileStore abstraction.
  • 3Auto-connect via a net-new set_connected(true) RPC.
  • 4Auto-select-star + calibrate on Start Guiding (net-new find_star/loop/cal-status RPCs).
  • 5Supervise + auto-restart on crash with capped backoff, re-writing the profile and re-issuing set_connected.

Security: a command/path-injection sink

ConnSpec.extra is attacker-influenceable by anyone who can write a profile, and the watchdog relaunches on a loop. So: an argv allowlist + path allowlist + no-user-strings-as-flags + port-4400 detect-and-refuse, landing in C5 independent of RBAC. This is exactly why config.backend is a privileged capability.

Incompatible-by-construction with NINA

In a NINA rig the guider already is PHD2, and NINA owns that process + its profile. A second managed phd2.exe would fight for port 4400 and overwrite the running profile. The picker hard-disables the toggle whenever any role resolves to NINA, and the orchestrator refuses the RigSpec server-side.

Guide scale ≠ imaging scale The pixel scale written to PHD2 is the GUIDE camera's (guide camera + guide-scope focal length), a physically distinct optical train from the imaging camera. Writing the imaging-train scale would make guide RMS and dither wrong by the guidescope/mainscope ratio — commonly 3–5×. Prefer letting PHD2's own calibrated scale drive RMS; the on-disk write only seeds an uncalibrated profile.

Set managed=false and AstroDeck simply connects to a user-run PHD2 — today's behavior, unchanged. The true "no separate binary" end-state is W4's NativeGuider.

W1.10 · Server-side sun avoidance

The sun is a hard floor,
not a banner.

Today _check_horizon returns early on a default site and only blocks alt < 0; goto force=true bypasses even that. On the common un-configured bench rig there is no protection against slewing at the sun. W1 closes it — as a W1 deliverable, not deferred.

The guard lives at the motion boundary

A cone wired only into /api/mount/goto is re-entered unguarded by sequence runs, meridian flips and polar routines. So the check sits inside goto_and_center and move_axis/slew — every internal re-slew inherits it.

  • Reuses the existing sun_altaz/sun_radec helpers (clockable via unix_time) and adds only the separation-cone check (default ~30°).
  • Independent of site.is_default — the daytime-bench accident is the default-site case.
  • goto force=true and a forced sequence/start are both subject to the cone — bypassable only with the dedicated config.solar_override capability.

Sun-cone & drift

Slew-triggered + periodic drift

The motion-boundary guard is slew-triggered — it can't see a target clear at flip time drift into the cone via sidereal tracking. So a periodic check on the status poller reuses sun_altaz against the current mount alt-az and fires the same SAFE-ING halt when a tracking mount crosses in. Dawn overtaking an unattended sequence is halted, not cooked.

Connect-time SAFE-ING action

On any connect, read the mount's pier/park state and alt-az. A real mount found unparked + tracking inside the cone is halted before any banner, escalated to a persistent header chip AND the alerts/escalation sink — so an absent operator is actually notified. Resume is gated by config.solar_override.

The meridian-flip pier gate is INVERTED

A strict "flip the guider calibration only on a confirmed pier change" gate is more dangerous than today's unconditional flip — the common real GEM is non-reporting (pier_side → UNKNOWN), so a confirmed-change gate would skip the flip after a real swap and run backwards / runaway RA.

1 · Classify the mount FIRST

Gate on a positive does-GEM-flip signal: _is_gem(side) OR does_meridian_flip — a mandatory new Telescope flag (ASCOM AlignmentMode==germanPolar; sim → True). Never keyed off time_to_meridian_flip() is None — that property is NINA-only and would mis-class the sim/Alpaca GEMs.

2 · Fork / alt-az → never flip

A mount with pier_side UNKNOWN and no positive flip flag is the only true non-GEM. It never needs a calibration flip — so the inverted rule cannot back-fire on it.

3 · GEM → flip unless KNOWN-unchanged

For any GEM, FLIP the calibration UNLESS pier side is known-and-unchanged. Treat UNKNOWN/non-reporting as "flip." Each guider's internal self-guard stays as the second line of defence.

W2 · Capability-based RBAC

Roles are bundles
of capabilities.

A route declares the capability it needs; the role just determines which capabilities a caller holds. The set is built by enumerating every mutating route in app.py, not an abstract taxonomy — and asserted exhaustively at boot.

viewer

VIEWER_LINK_CAPS

view.status view.preview

Live-watch only. Excludes view.media (raw FITS) and view.site_precise (precise lat/lon) by default.

operator

imaging + guiding

view.statusview.preview control.capturecontrol.guide

Deliberately excludes control.mount, control.power, every config.*. Can run a capture/loop + guiding, but cannot start a slewing sequence.

admin

ALL_CAPS

control.mountcontrol.power config.safetyconfig.backend admin.users

Everything — incl. view.media and view.site_precise. Destructive caps double-confirm even for admins.

Privilege-escalation fix — control.mount from the MOTION boundary control.mount is re-derived by enumerating every route whose handler transitively reaches slew/move_axis/set_tracking/park/unpark/pulse_guide — including the sequence engine, polar, sequence/recover and mount/solve_sync. An operator holding only capture + guide could otherwise drive a real mount across the sky. The boot check is a static route→motion-sink declaration (reaches={"SequenceEngine.start"}), not infeasible runtime call-graph inference: a route declared reaching a motion sink but tagged control.capture fails create_app().

Field-level enforcement on multi-domain routes

POST /api/config merges any subset of {site, safety, escalation, alerts, deadman_url} in one call. A single route-level Depends would let one config cap mutate all of them.

  • Presence read from model_fields_set, not value-vs-default (setting a value to its default must not evade the check).
  • Fail-closed for any unmapped block — reject the whole body 403, merge nothing.
  • Mixed allowed/disallowed bodies rejected atomically — persisted config unchanged.
  • auth/remote are pinned to admin.users and kept off the general route — a config.alerts holder flipping provider="none" would disable all auth in one request.

SSRF + credential-exfil sinks

config.alerts stores attacker-controllable url/token; .../test makes a real outbound request to it. Under WAN exposure that is an SSRF primitive and an exfil path.

  • Enforce the existing alerting._url_is_safe at the route/merge layer — reject loopback / private / link-local / metadata before any outbound call.
  • deadman_url keeps its allow_private=True exception (a self-hosted LAN monitor is legitimate) — but multicast/reserved/unspecified are still blocked.
  • Asymmetric signing (EdDSA/RS256) — the relay never holds home signing authority, so a relay compromise can't mint admin tokens. revoked_jti is append-only and admin.users-gated.

Pluggable identity

none (default) resolves every caller to admin — today's LAN behavior, byte-for-byte. google is OIDC Authorization-Code + PKCE: verify the ID token, bind state/nonce, require email_verified, pin hd, then map email → role via an allowlist re-evaluated on every request.

default_role is capped at viewer (or a non-empty google_hd is required) so a non-null default can't grant the whole Google population elevated WAN access.

Viewer surfaces are read-only — not 403-on-tap

  • The UI reads its principal/caps (/api/me, view-required, fail-closed 401) and renders viewer surfaces read-only.
  • Fail-closed render: until caps resolve, motion/power/config controls are disabled/hidden — an unknown role is treated as viewer, not admin (no flash of an actionable slew pad).
  • Viewers get no motion controls including STOP — the operator is the safety authority; the background panicStop 403 is swallowed silently.
  • Three look-alike dead-ends get distinct copy: 403 → "view only", 1008-expiry → "your link expired", transport → "reconnecting." Per-view gating is per-role, not one sticky rig-wide flag.
W3 · gRPC cloud relay

The home dials out.
No port-forwarding.

Remote is purely transport. The home server dials OUTBOUND to a small cloud relay and holds a persistent gRPC bidi stream; remote browsers reach the relay over HTTPS + Connect. We tunnel the existing HTTP/WS and replay it against the in-process ASGI app — reusing the entire current UI + REST + W2 RBAC, no parallel API.

Relay topology

One Tunnel RPC per stream-class

A 40 MB raw FITS would HOL-block the status/guide channel if it shared one flow-control window. So the home opens three concurrent Tunnel streams — event, control, bulk-media — for true per-class flow control. Bodies stream in bounded chunks, never one atomic bytes.

Principal injection is the crux

The replay strips all inbound auth headers and injects the principal only from a relay-signed, home-verifiable token. The scope is flagged REMOTE/untrusted — no loopback shortcuts — and a control route still 403s at home (the relay's stamp is advisory; the home is authoritative).

One bus subscription, fanned out

The relay is a single bus.subscribe(), then per-ws_id bounded buffers. A slow viewer's buffer fills and that viewer alone is dropped — never blocking the shared stream. Per-viewer seq makes a drop a detectable gap → re-snapshot.

Residual trust — the relay is a plaintext MITM (accepted risk) TLS terminates at the relay, so a compromised relay can read all tunnelled traffic and act as any already-authenticated viewer — though token minting is withheld by asymmetric/home-issued signing. Mitigations: optional mTLS; admin/config.* writes are unreachable over the tunnel regardless of principal (auth.config/remote.config/the revoke API all tunnel-blocked); and control.mount/control.power default to a directly-exposed home only.

Scoped viewer links

A GET /share/{token} mints a short-lived viewer-only JWT — signed with a separate viewer-link key so a link-minting bug can never forge an admin session. It carries an explicit cap set, a unique jti in the deny registry (revocable before exp), a TTL + renew-while-connected, max concurrent viewers, and per-link audit logging.

Redaction is server-side

hub.summary() takes a caps parameter: a viewer lacking view.site_precise gets coarsened coordinates, lacking config.site_optics gets the site/alert/safety blocks stripped — before the frame reaches the queue. Each ws_id's WsEvent.json is scope-specific, not globally identical. A revoked viewer's open /ws is torn down within ≤ 30 s via a home-pushed RevokeSignal.

W4 · Roadmap (brief)

All of W4 is more registrations.
Zero hub edits.

Not built in this program — specced here only so the W1 seam is sized for it. Every item below lands as additional Backend registrations against the same BackendSession contract.

NativeGuider

In-process multi-star centroiding on the guide camera + mount pulse_guide — the true "no separate binary" end-state that retires managed PHD2. The real lift is calibration: it must re-implement per-axis mount-response measurement PHD2 provides for free, plus additive per-axis guide-rate Telescope methods (none exist on the ABC today).

Native / INDI / Rust drivers

Talk a native SDK straight to ZWO / Pegasus / QHY where it is faster or richer than Alpaca. The deferred rotator (camera PA across a flip), dome/roof, and CoverCalibrator/flat-panel roles land here — sized to include sequence-engine integration, not bare device classes.

NINA → Rust port

The eventual replacement of the NINA bridge with a Rust service exposing the same BackendSession contract. The harness means the UI and hub never know the difference — the bridge was always meant to be temporary.

The through-line Every safety hole closed at the boundary. Every backend choice reduced to data. Every role tagged, verified at both ends, and read-only by default. AstroDeck is the controller you own — vendor-neutral by construction, from the daytime bench to a friend watching the live stack from across the world.
